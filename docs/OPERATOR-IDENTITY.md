# Employee identity and internal number

The RU deployment compiles and prerenders the exact source on its Actions runner using the pinned Puppeteer builder and a whitelist of the server's existing public frontend build arguments. Backend environment variables and credentials never leave the server. Only changed compiled static files, nginx configuration and release metadata are transferred over SSH. Unchanged static files are copied from the exact still-running frontend into a new, isolated build context; stale files are pruned there, and the entire resulting tree must match the new CI build's complete SHA256 manifest before deployment. The serving container is never edited. The server also verifies transport checksum, safe paths, source SHA, app version and unchanged public build configuration. Transport archives are removed after a healthy deployment; verified runtime contexts and Compose overrides remain under `/app/aipbx-frontend-releases/<run>-<attempt>` for rebuilds. Other targets retain their existing build path. Upload verifies the production Ed25519 host fingerprint; deliberate host-key rotation requires updating its public pin after trusted verification. Private-key files exist only in a protected runner temporary directory and are removed on success or error. The nginx healthcheck uses IPv4 loopback because this nginx configuration does not listen on IPv6 localhost.

Operator analytics cards and topic drill-downs use the optional stable `operatorId` returned by the backend. Names remain display labels; the per-call `operatorExtension` is shown separately in call lists/detail and can be supplied in manual uploads. Existing responses and links without identity continue using names. Same-name staff with distinct IDs keep distinct rows and drill-downs.

The `/calls` table renders the two stored fields compactly as `Name (extension)` in one line, without an extra number label. This formatted string is only a view value: it is never saved as the employee name or used as a grouping key. Records without an extension keep their existing name display.

This frontend requires the compatible additive backend release first; target only aipbx.ru through GitHub Actions `[deploy:3]`. It does not change source credentials, models or GPU services. History backfill is a separately backed-up, account-scoped operation; recordings and metrics are not regenerated.

The API snapshot/generated declarations include optional identity/extension fields and ID query filters. Validate full unit tests, production build/prerender, ESLint and generated-type consistency before release, then verify the installed dashboard/filter flow. Coordinator/evidence is the helpdesk EM-20261019-333 identity plan; private production backups and staff mappings are never committed.

aipbx.ru has restricted SSH. The RU-only Actions job publishes its ephemeral runner IPv4 and release identifiers, then waits up to 15 minutes for a verified, authorized IPv4/32 TCP/22 exception. The helper never edits the firewall or receives its credentials. Schedule automatic rule deletion after 20 minutes before opening access; remove it immediately after release. Other targets and existing trusted-address rules remain unchanged. See the corresponding backend release notes for the operator procedure.
