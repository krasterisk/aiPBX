<objective>
Deliver the drill-down the phase is named for: from a ranking row to an operator's metrics, from a metric to the quotes and rationale that produced it, from a quote to the full call — all inside one stacked side panel with a working back path (D-01, D-02, D-03), scoped to the dashboard's own filters (D-06), and silently omitting metrics the backend had no evidence for (D-08).

Purpose: this is the phase's headline user value — the answer to «почему у оператора такая оценка» without leaving the dashboard. It is also the plan that connects the two W1 tracers: the bounded evidence endpoint from 10-01 and the panel shell plus stack model from 10-02.
Output: the Report API and type additions, a hoisted metric-presentation module, the panel body router with its operator and call bodies, clickable ranking rows, and the single panel host on the dashboard.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| server response → DOM | Quotes, rationales, operator names and call metadata render inside the panel |
| user selection → API request | Operator name, metric id, period and project become query parameters |
| panel lifetime → browser | Customer speech is present in the page while the panel is open and in the query cache after it closes |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-10-06-01 | Tampering | quote and rationale text rendered in the panel | high | mitigate | All server text renders as React children; `dangerouslySetInnerHTML` is not introduced in any panel file. Quotes are visually distinguished by styling, never by injected markup. |
| T-10-06-02 | Information Disclosure | customer speech retained in the query cache after close | medium | mitigate | Evidence is fetched under the existing operator-analytics cache tag, so a filter change or a logout-driven reset invalidates it with the rest of the dashboard data; no separate long-lived cache entry is introduced. |
| T-10-06-03 | Information Disclosure | panel state outliving the panel | medium | mitigate | The stack is component state only — no URL, store or web-storage write — so closing the panel discards which operator and which call were being inspected (D-07). |
| T-10-06-04 | Elevation of Privilege | client-supplied operator name or project id reaching another tenant's data | high | accept-with-note | Enforcement is server-side: the evidence and list endpoints pin a non-admin caller to its own tenant regardless of parameters (T-10-01-01, T-10-05-04). The client adds no authorisation logic, which is the correct division; this row exists to record that the client is not the control point. |
| T-10-06-05 | Denial of Service | unbounded evidence rendering | low | mitigate | The response is bounded server-side (per-metric cap and sampled calls); the panel renders what it receives and adds no unbounded client-side expansion. |
| T-10-06-06 | Repudiation | evidence read not attributable | low | mitigate | The audit line is written server-side per read (T-10-01-05); the client adds nothing and must not suppress the request by caching across users. |
| T-10-06-SC | Tampering | package-manager installs | low | accept | This plan installs nothing; 10-RESEARCH.md § Package Legitimacy Audit records zero new packages for the phase. |
</threat_model>
