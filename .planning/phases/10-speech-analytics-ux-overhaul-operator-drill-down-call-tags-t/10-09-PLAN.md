<objective>
Put themes where managers work: chips on the journal row and the call card with a bounded overflow treatment (D-19), an editable chip row on the call card that corrects a call's tags through the manual endpoint with optimistic feedback and honest failure handling (D-14, D-22), and one «Теги» column in the export (D-23).

Purpose: automatic tagging is only trustworthy if a manager can see the tags in context and fix a wrong one in two clicks. The export column is what makes tags usable in the spreadsheets these teams actually report from.
Output: one shared chip row component, its two integrations, and one export column.
</objective>

This is the placement decision the design contract left open, and the entity is the correct home: the tag data is part of the analytics record, both the journal feature and the call card render it, and an entity may not import from a feature — so putting it in the journal feature would make the call card's use of it a layering violation.

    Take the theme id list, the name snapshot, the project taxonomy, a bounded-or-unbounded display mode and an optional editing configuration. Resolve each name from the snapshot first, then the taxonomy, then the identifier — snapshot first is what keeps a renamed or deleted theme readable on a historical call, and reversing the order would silently rewrite history in the journal. Render the no-themes case as short inline label-size text, not as an empty region and not as a section-style empty state.

    Give the component an editable mode that renders a remove control per chip with an accessible name naming the theme and an add control, both reporting upward — the component performs no mutation of its own, which keeps it usable in the journal where editing is not offered. Export it from the entity's public surface.

    Write the test file covering the nine behaviours above.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| stored theme names → DOM | Names render as chips, overflow hover text, and picker options |
| stored theme names → spreadsheet file | Names are written into an exported sheet opened by a desktop application |
| client → API | The resulting theme set for one call is sent to the manual update endpoint |
| optimistic state → user belief | The card briefly shows a state the server has not yet confirmed |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-10-09-01 | Tampering | spreadsheet formula injection through a theme name in the export | high | mitigate | The new column's values are written so a leading formula character is displayed as text. The pre-existing exposure on other columns is recorded as a backlog finding rather than expanded into this plan. |
| T-10-09-02 | Tampering | stored cross-site scripting via a theme name in a chip or hover text | high | mitigate | Names render as React children and the full list uses the native hover attribute, never injected markup; names were length- and content-capped at the 10-03 write boundary. |
| T-10-09-03 | Elevation of Privilege | tag edit on a call in another tenant | critical | accept-with-note | Enforcement is server-side: the update endpoint asserts record access before writing (T-10-05-01). The client adds no authorisation logic, which is the correct division; this row records that the client is not the control point. |
| T-10-09-04 | Tampering | ad-hoc theme bypassing the controlled vocabulary | medium | mitigate | The picker offers project taxonomy themes only, and the server independently rejects a theme id outside the project's taxonomy (T-10-05-06) — defence on both sides. |
| T-10-09-05 | Repudiation | an optimistic state mistaken for a saved state | medium | mitigate | A rejected save restores the previous set and reports the failure with explicit copy; a spec case drives the failure path. |
| T-10-09-06 | Information Disclosure | theme names in an exported file leaving the tenant | low | accept | The export already carries transcript-derived analytics for the caller's own calls; theme names add no new data class, and export remains subject to the existing per-call access checks. |
| T-10-09-07 | Denial of Service | very many themes on one call bloating a journal row | low | mitigate | The journal mode caps at three chips plus a counted overflow chip; the per-call theme count is capped server-side in 10-05. |
| T-10-09-SC | Tampering | package-manager installs | low | accept | This plan installs nothing; 10-RESEARCH.md § Package Legitimacy Audit records zero new packages for the phase. |
</threat_model>
