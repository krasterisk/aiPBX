<objective>
Turn the call-analytics dashboard into the information architecture Phase 10 promises: single scroll, stats first, AI insights right after them, mid-charts (or the custom builder grid) next, ranking last (D-24, D-25, D-26, D-28) — with the analytics-cost section deleted (D-09), the two volume-duplicating charts dropped from the fixed layout while remaining available as builder widgets (D-11, D-12), the cost stat cards kept (D-10), and manager-first section spacing (D-27).

Purpose: this is the "информативность без перегруза" half of the phase goal and the prerequisite for everything the drill-down plans add — the panel host, the «Темы» section and the ranking call-to-action all land in this file, and reshuffling it once, under test, is much cheaper than reshuffling it three times.

It also closes a latent defect that D-29 would otherwise make user-visible: the dashboard resolves its active project with a strict comparison between a string from the query parameter and a number from the wire, so a fresh load of a project deep link silently renders no project-scoped sections at all.
Output: the module's first render test plus a reordered, lighter dashboard.
</objective>

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |

| T-10-04-01 | Information Disclosure | project id from the query string selecting project-scoped data | medium | mitigate | Normalising the comparison only changes which of the caller's **own** projects is matched — the project list itself comes from a tenant-scoped endpoint, so a foreign id resolves to nothing and renders no data. | T-10-04-02 | Tampering | project names and payload strings rendered as section labels | low | mitigate | All values render as React children; no raw-HTML injection is introduced anywhere in the reshuffle. |
